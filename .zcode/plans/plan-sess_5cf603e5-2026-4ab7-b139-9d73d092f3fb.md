# 后端补全方案：Node.js + Express + MySQL

## 背景

- 前端为纯 Mock 原型：页面直接 `import src/mock/*` 数组，无 service 层；仅 Orders 页有写操作（内存态，刷新丢失）。
- 目标：搭建 REST API 后端，用真实 MySQL 持久化，前端切换到 API 取数，订单操作落库。

## 一、后端（新建 `server/` 目录，与前端同仓库）

**技术**：Express 4 + mysql2（连接池）+ dotenv；TypeScript 可选，先用 JS 保持轻量。

### 1. 数据库（数据库名 `am_database`）
- 建表脚本 `server/db/schema.sql`：6 张主表按 `src/types.ts` 生成——`materials`（含化学成分 11 元素列或 JSON 列）、`parts`、`equipment`、`inspections`、`standards`、`orders`（含 process_parameters、schedule_info 用 JSON 列）。
- 关联关系（relatedParts 等 id 数组）用关联表或 JSON 列存，读取时由后端组装回 `types.ts` 的形状（前端类型零改动）。
- 种子脚本 `server/db/seed.js`：把 `src/mock/mockData.ts`、`mockOrders.ts` 的 47+8 条数据导入，保证前端展示与现在一致。

### 2. API（按现有页面消费模式设计）
- `GET /api/materials|parts|equipment|inspections|standards` — 全量列表（页面本就整表加载+前端筛选，保持该模式改动最小）
- `GET /api/:entity/:id` — 详情
- 订单（服务端承载业务逻辑，README 建议项）：
  - `GET /api/orders`、`POST /api/orders`
  - `PATCH /api/orders/:id/status` — 服务端校验 `statusTransitions` 状态机（含回退）
  - `POST /api/orders/:id/match` — 绑定设备 + 生成工艺参数
  - `POST /api/orders/:id/schedule` — 写入排产信息、计算队列位置
- `GET /api/search?q=` — 全局搜索（移植 Dashboard 中的搜索逻辑）
- 统一错误处理 + 简单请求日志。

### 3. 运行
- `npm run dev`（server 目录，nodemon）监听 `http://localhost:3001`。
